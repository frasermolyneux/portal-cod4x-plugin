# Plugin Runtime

## Local configuration

The runtime loads `portal-cod4x-plugin.config.json` during startup. Required fields:

- `tenantId`
- `clientId`
- `clientSecret`
- `repositoryApiBaseUrl`
- `repositoryApiResource`
- `gameServerId`
- `refreshIntervalSeconds` (15-900)

If the file is missing or invalid, runtime settings retrieval is paused and retried with backoff.

## Startup broadcast behavior

When the plugin is loaded (`OnInit`), it sends a broadcast message to all players using CoD4x chat:

- Chat prefix: `^4[^1XI-BOT^4]^7`
- Broadcast format: `^4[^1XI-BOT^4]^7 Portal Plugin is online (version <version>)`
- Startup log format: `Portal Plugin is online (version <version>)`
- Target slot: `-1` (broadcast/all players)

The startup message is generated by `BuildOnlineBroadcastMessage` and dispatched by `InitializePlugin`.

## Scheduled settings loop

After startup, the runtime performs periodic refreshes:

1. Acquire Entra access token via client-credentials.
2. Fetch global `cod4xCommands` configuration.
3. Fetch server-level `cod4xCommands` override for configured `gameServerId`.
4. Build effective command map: built-in defaults -> global overrides -> server overrides.
5. Reconcile command powers only when effective `cod4xCommands.enabled` is true.

When effective `cod4xCommands.enabled` is false, reconciliation is skipped and existing in-server command powers are left unchanged.

## CoD4x ABI wiring

The plugin exports:

- `OnInfoRequest(pluginInfo_t*)`
- `OnInit()`
- `OnFrame()`
- `OnClientAuthorized()`
- `OnTerminate()`

`OnInfoRequest` advertises handler compatibility `4.000` and plugin `major.minor` derived from build-time version settings.

`OnFrame` and `OnClientAuthorized` both pump runtime `TickPlugin` so periodic settings refresh can continue while the server is active.

## Ban diagnostics

The plugin registers two RCON ban-list commands at default power 30:

- `dumpbanlist` emits only server-originated bans waiting for the portal agent to import them.
- `dumpportalbanlist` emits every portal-synchronized ban currently held in the plugin's enforcement cache.

`dumpportalbanlist` renders one line per cached ban with its CoD4x player identifier and enforcement reason, followed by an `Active portal bans` count. Portal bans remain excluded from `dumpbanlist` so the agent cannot re-import portal-owned records as new server bans.

## Connection correlation

Observed player connections receive a UUID shared by their connect event and VPN evaluation.
Disconnect events include that UUID when the connection is known. A player already present
when the plugin loads, or carried across a map change without provable continuity, has a
null connection ID; the plugin logs the uncertainty and such a player must not be treated as
a fresh Siege admission. An observed new connection receives a new UUID.

If a real IP arrives after the connect event, the plugin also emits a
`player-ip-resolved` event with the player GUID, slot and nullable connection ID.
Both event types mark plugin-owned protection evaluation so consumers do not duplicate it.

## Siege evaluation

Observed connections are evaluated with `siegeEvaluation` enabled, first with a GUID only if
the IP is unavailable and again when a real IP arrives. The existing VPN decision remains
independent. Unknown connection continuity is passed as a null connection ID and is not
eligible for a Siege kick.

A Siege decision must explicitly specify `mode: "Enforce"` and match the live GUID, slot,
connection ID and generation, with an unexpired decision. The plugin invokes CoD4x's
`Plugin_DropClient` directly with the kick reason and reports `Dispatched`, which does not
confirm that the player was dropped. Stale or invalid decisions are reported as `Stale` or
`Failed`. Outcome reports are retried while the plugin runs; a process restart can leave
unacknowledged outcomes pending for reconciliation.

Dry-run matches are recorded by the service and return no dispatchable Siege decision.
Unknown or missing decision modes also fail open. VPN Protection can still enforce its own
independent decision during a Siege dry run.

## Version source

Version is sourced from `version.json` and injected by CMake into compile definitions:

- `PORTAL_COD4X_PLUGIN_VERSION`
- `PORTAL_COD4X_PLUGIN_VERSION_MAJOR`
- `PORTAL_COD4X_PLUGIN_VERSION_MINOR`

This ensures the online broadcast and plugin metadata remain consistent with the configured plugin build.
